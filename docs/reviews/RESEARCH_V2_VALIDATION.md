## 第一轮独立审核发现并已修复的问题

- debug 与 evidence 使用不同参数时，账本可能写入并未实际执行的随机种子；
- 复现和消融缺少可执行的比较条件；
- 多个 Framework 可能产生重复实验编号；
- 空测试、空 CUDA 探针和手填相同成绩可能冒充外来 Framework 验证通过；
- 原始 NPZ 可能进入 Git，64 MiB 上限也不适合真实数据；
- 创新“Run 已确认”和“创新值得接受”没有分开；
- pending 方向可从底层入口绕过；
- 普通 Git 历史包含已经删除的个人实例，不能直接上传。

对应修复已经进入当前代码，并增加了反例测试。功能复核、Ultra 反例复核和实际发布树复核均重新执行当前代码并给出 `PASS`，没有沿用第一次结论。发布树复核确认零父提交、350 个文件、禁止路径 0、个人与密钥特征 0。

## 当前明确限制

- 外来代码会以当前 Windows 用户权限执行。信任确认不是操作系统沙箱，只能对已人工审读的可信代码使用。
- 单个 NPZ 当前上限为 1 GiB；更大文件需要分片，或等以后增加流式格式。
- 只有 GZSL 可运行，另外五个方向只是待做身份。
- 系统不自动下载数据和权重，不自动 push、发布、训练高成本正式任务或写论文。
