# 通用科研工作流使用说明

## 1. 安装并检查

在 PowerShell 中进入唯一根目录：

```powershell
Set-Location 'D:\智能双流系统'
.\tools\install-research-workflow.ps1
.\tools\install-research-workflow.ps1 -Check
```

安装器会做三件事：确认固定 Python 能看到 CUDA、生成仅供本机使用的 `config/environment.local.json`、把 Codex 通用 Skill 连接到项目正式源码。它不会建立个人实例，也不会修改 PaperFlow。

## 2. 先看通用模板

双击 `启动工作流.bat`，打开 `http://127.0.0.1:18082/`。

此时应看到：

- 页面状态为通用模板；
- 六方向全部显示；
- 只有 GZSL 标记为可用；
- 页面没有个人名字和论文操作；
- 环境显示 `dvsr_gpu`、CUDA 和当前显卡。

## 3. 用户决定后再实例化

```powershell
.\tools\instantiate-workspace.ps1 `
  -DisplayName "我的 CV 科研工作流" `
  -Slug "my-workspace"

.\tools\activate-workspace.ps1 -Slug "my-workspace"
```

实例只会建立：

```text
users\my-workspace\
├─ workspace.json
├─ REPOSITORY_INDEX.json
├─ SKILL.md
├─ repositories\
├─ deliveries\
├─ inbox\
├─ materials\
└─ .runtime\
```

已经存在的实例绝不覆盖。个人论文和文献库不在科研阶段预建。

## 4. 选择方向后才建仓库

刷新页面，选择 GZSL 并填写仓库名，例如 `my-gzsl`。仓库只会创建在当前实例的 `repositories\` 中。

另外五个方向保持待做，因此不会产生空仓库。

## 5. 接入外来 GZSL 代码

先把外来代码准备为本机干净 Git 仓库，并人工阅读它会执行的测试、入口和脚本，然后：

1. 在页面填写仓库路径并扫描。
2. 查看系统给出的入口和八类组件候选。
3. 人工修正数据、模型、损失、训练、评估、推理、指标和配置文件；每类可以填写多行。
4. 明确信任后生成受控草稿。源仓库不会被修改；失败现场会保留，便于检查。
5. 在草稿中完成 `workflow_adapter.py`，用相同数据和划分比较 `S/U/H`。
6. 保存两份真实结果文件。每份都要绑定同一数据清单、可重跑的 Python 命令、代码提交和输出文件哈希，并由两名不同复核人确认；登记时系统会在临时 Git 快照中重新执行两条命令，结果和产物必须逐项一致。
7. 只有真实测试、CUDA 检查和等价检查都通过后，才在高级区域登记为稳定 Framework。

扫描只是按文件名和路径给建议，不代表系统已经理解或证明代码正确。

“我信任这份代码”也不是操作系统沙箱：验证会执行外来代码，所以只对已经人工审读、来源可信的代码勾选。未知代码应先在单独的受限机器或容器中审查，不能直接在日常电脑上运行。

## 6. 跑四类实验

| 类型 | 编号示例 | 是否绑定 Idea | 能否产生子 Framework |
|---|---|---:|---:|
| 复现 | `repro-001-cub` | 否 | 否 |
| 调参 | `tune-001-lr` | 否 | 否 |
| 消融 | `ablate-001-align` | 否 | 否 |
| 创新 | `innov-001-new-head` | 是 | 确认成功后可以 |

四条路线都先填写自己的比较规则：

- 复现：来源、目标成绩、允许误差、代码标准和数据标准；
- 调参：允许改变哪些参数；
- 消融：关闭哪个模块、如何关闭、与哪个启用结果比较；
- 创新：已确认基线的“实验编号/Run 编号”、真实基线成绩、目标指标和至少要提高多少。

创建实验后先创建其 Worktree。先跑 `debug` 检查流程，再用完全相同的配置与随机种子跑 `evidence` 形成正式证据；系统会拒绝中途改配置。每个 Run 都保存提交、配置、数据身份、日志、`S/U/H` 和文件哈希。实验编号在整个仓库中唯一，即使一个仓库有多个 Framework 也不会重号。

## 7. 登记真实数据

在页面选择 NPZ 数据文件，填写数据集名称、版本、来源地址和许可证。系统会检查内容并生成 SHA-256 清单，原始数据仍保留在原位置，不会复制进仓库，也不会被 Git 提交。

当前单个 NPZ 最大支持 1 GiB，并同时限制压缩包成员数和解压后总大小，避免损坏文件或压缩炸弹。科研交付包不会写入本机绝对路径，只保存可核对的数据哈希身份。

## 8. 人工确认与科研交付包

只有人工复核过的 `evidence` Run 才能确认。确认后可以生成科研交付包，但这仍然不会自动写论文。

创新实验要另外明确选择“接受”或“拒绝”，并写结论。系统会从引用的已确认基线 Run 读取真实指标，不接受自行填写或不存在的基线。只有结果达到预先写下的最低提升、人工选择接受，而且对应提交一致，才能晋级成稳定子 Framework。

合成小数据只能证明流程能跑通，不能当成论文成绩。

## 9. 停止

双击 `停止工作流.bat`。它只停止科研页面服务，不关机、不删数据、不停止 PaperFlow 的独立服务。
