# 代码与来源规则

## Framework 必须完整

Framework 是可以独立完成数据读取、训练、评估和推理的代码主体。关闭研究改动后，它仍应回到稳定基础行为。

一个复杂组成部分可以分布在多个 Python 文件中，只要能解释：

- 输入和输出；
- 依赖关系；
- 接入位置；
- 配置开关；
- 关闭后的行为；
- 验证方法。

## 建立基础 Framework

可以比较多份论文代码和官方实现来理解共同规则，但不能把多个仓库随意拼接成自己的主干。应先固定：

- 数据接口和划分；
- 模型输入输出；
- 损失与优化步骤；
- 评估指标；
- 推理产物；
- 可插入研究改动的位置。

随后独立建立自己的可运行基础 Framework，并记录参考来源。

## 接入一个研究改动

只修改当前想法需要的部分。默认不改变公共训练循环、数据划分或评估口径；确实必须改变时，要把变化明确写进实验比较规则。

关闭研究改动后应恢复基础行为。这里要求流程、配置和评估口径恢复，不要求随机训练指标逐位相同。

## 来源和许可证

每个外部来源至少记录：

- 论文或项目标题；
- 官方页面或仓库地址；
- 精确提交或版本；
- 许可证；
- 实际借鉴的部分；
- 是直接使用、允许范围内改写，还是只参考思路。

许可证不清楚时只能研究和记录，不能把代码合并进可发布模板。

## 冻结与复核

正式 Run 绑定精确 Git 提交。工作树必须干净，运行配置、数据身份和评估规则必须冻结。复核时以仓库文件和产物哈希为准，不以口头说明为准。
