[测试样本，非用户文档]

`demo-user`，建议采用“工具仓库与论文仓库分离、项目内只新增 3 个工作流文件”的方案。当前只给出方案，不修改磁盘。

本地建议这样放：

```text
D:\tools\research-workflow\     # 克隆的工作流工具，独立维护
D:\research\my-paper\           # 新论文项目，独立 Git 仓库
```

论文项目的最小结构：

```text
my-paper/
├─ AGENTS.md                    # 告诉助手如何处理自然语言想法和实验
├─ LAB_NOTEBOOK.md              # 追加式科研日志，作为事实来源
├─ .gitignore                   # 排除数据、权重、运行产物和密钥
├─ src/                         # 代码；真正需要时再创建
├─ configs/                     # 可复现实验配置；有实验时再创建
├─ paper/                       # 论文正文、图表源码
├─ data/                        # 本地数据，不上传 GitHub
├─ runs/                        # 日志、预测结果、临时产物，不上传
└─ checkpoints/                 # 模型权重，不上传
```

初始化时只立即建立前三个文件，其余目录等第一次用到时再创建，不用 `.gitkeep` 占位。

`AGENTS.md` 约定助手：

- 收到“想法：……”时，为其分配 `I-日期-序号`，追加到 `LAB_NOTEBOOK.md`。
- 收到“实验：……”时，为其分配 `E-日期-序号`，整理假设、基线、唯一改动、数据集、指标、随机种子、资源和状态。
- 信息不完整但不影响安全时标记为“待定”，不擅自编造。
- 真正运行前记录代码提交、配置和完整命令；结果出来后追加指标、异常、结论及是否值得继续。
- 日志只追加、不覆盖历史；失败实验也保留。
- 不自动上传、发布、删除数据或覆盖已有结果。

以后可以直接这样说：

```text
想法：给检测头加入尺度感知门控，可能改善小目标 AP。
```

```text
实验：以当前最佳模型为基线，只加入尺度感知门控，
在相同数据划分上跑 3 个随机种子，主指标看 AP_small，
显存尽量控制在 24GB 内。
```

```text
结果：E-20260712-01 已完成，三个种子的 AP_small
分别是 24.1、24.5、24.3，训练时间增加约 8%，这个方向保留。
```

本地与 GitHub 的放置原则如下：

| 内容 | 本地 | GitHub |
|---|---:|---:|
| `AGENTS.md`、`LAB_NOTEBOOK.md` | 保留 | 提交 |
| 源码、实验配置、论文源码 | 保留 | 提交 |
| 小型结果表和最终图表源码 | 保留 | 提交 |
| 原始数据、运行目录、缓存 | 保留 | 不提交 |
| 模型权重、预测大文件 | 保留或放对象存储 | 默认不提交 |
| `.env`、令牌、密钥 | 保留 | 严禁提交 |

`.gitignore` 至少覆盖：

```gitignore
data/
runs/
checkpoints/
*.pt
*.pth
*.ckpt
.env
__pycache__/
```

GitHub 上只创建论文项目仓库，例如 `your-name/my-paper`。不要把工作流工具源码复制进论文仓库，也不要形成嵌套 Git 仓库；通过安装版本或固定提交号引用工具即可。只有需要修改工具本身时，才单独 fork 工具仓库。
