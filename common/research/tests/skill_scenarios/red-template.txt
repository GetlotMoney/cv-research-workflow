[测试样本，非用户文档]

`demo-user`，结论：我会新建一个“实验覆盖层（overlay）”模板，不改旧 Trial，也不复制基础模型仓库。论文官方代码只作为可追溯参考，基础模型以固定 Git commit 的外部依赖接入。首次运行先验证基础模型等价性，再做最小 GZSL 对照实验。

执行顺序如下：

1. 锁定来源
   先确认论文标题/版本、论文链接、官方代码仓库和基础模型仓库。若缺少具体论文或仓库信息，不会猜测链接或把第三方复现冒充官方代码。官方身份需由论文项目页、作者主页或论文与仓库的相互引用验证。

2. 选择模板
   优先采用基础模型仓库原生的训练、配置和数据接口，在新的独立仓库中增加轻量适配层。只有基础模型没有可复用入口时，才考虑通用 PyTorch/Hydra 模板，避免额外框架成为实验变量。

   最小结构建议为：

   ```text
   gzsl-idea-exp/
   ├─ README.md
   ├─ experiment.yaml
   ├─ configs/
   │  ├─ smoke.yaml
   │  ├─ baseline.yaml
   │  └─ idea.yaml
   ├─ src/
   │  ├─ method.py
   │  ├─ base_model_adapter.py
   │  └─ gzsl_metrics.py
   ├─ tests/
   └─ scripts/
   ```

   文档只保留一页 README；来源、版本、配置和运行事实集中放进 `experiment.yaml` 与每次运行的自动 manifest。

3. 接入外部基础模型
   若基础模型可安装，使用锁定 commit 的 Git 依赖；否则通过明确的仓库路径和 adapter 接入。记录基础仓库 commit、remote、分支与 dirty 状态，不直接改其代码，也不把代码复制进实验仓库。

4. 从论文想法落到代码
   把论文中的具体章节、公式或模块映射到 `method.py`，并明确：

   - 原论文做了什么；
   - 本实验新增或迁移了什么；
   - 哪些地方严格复现，哪些地方因基础模型不同而调整；
   - 唯一实验变量是什么；
   - 预期影响 seen、unseen 与调和平均值 H 的因果链条是什么。

5. 首次运行
   首次运行不是直接跑完整训练，而是依次通过：

   - GZSL seen/unseen 类别集合无交叉检查；
   - 指标单元测试；
   - 基础模型原生结果与 no-op adapter 结果等价性检查；
   - 小数据、短 epoch 的 smoke run；
   - 同一 seed、同一数据、同一超参数下的 baseline/idea A-B 对照。

   通过条件包括：无 NaN、模型可保存并重载、seen/unseen/H 指标齐全、基础模型结果在预设误差内一致。首次 smoke 只证明实现正确，不据此声称方法有效；随后才运行至少 3 个种子的正式实验。

必须保存的事实包括：

- 论文标题、作者、年份、版本、DOI/arXiv URL、访问日期及 PDF 哈希；
- 想法所在页码、章节、公式或图表，以及“论文原始 claim”和“本实验假设”的区别；
- 官方代码 URL、官方身份依据、commit/tag、许可证；
- 基础模型仓库 URL、commit、分支、dirty 状态和许可证；
- 数据集来源、版本、下载校验值、预处理方式、seen/unseen split；
- 指标定义，尤其 seen accuracy、unseen accuracy 和调和平均值 H；
- 完整解析后配置、随机种子、命令、环境锁文件、CUDA/PyTorch 版本与硬件；
- 实验仓库 commit、外部仓库 commit、运行日志、原始指标和失败原因；
- 论文实现与本实验之间的所有偏离及其理由；
- 成功、失败和停止标准，避免看完结果后再改判定口径。

真正开始前只需要两项关键输入：论文的准确标识或 PDF，以及基础模型 Git 仓库路径/URL。若上下文已有，直接使用，不重复追问。本轮未读取或使用 `cv-experiment-workflow`，也未修改任何文件。
